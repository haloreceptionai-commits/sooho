- Advanced Video AI finishing draws frames with the Blender engine via hosted-renderer/cartoon/blender_bridge.py (shots planned by blender/art_director.py, two Blender lanes per machine, Cycles on the card because Azure's T4 driver exposes no working EGL/Vulkan for Eevee — measured 27 s/frame software vs ~1 s/frame Cycles; BLENDER_ENGINE=eevee only where a GPU display driver exists) on the scale-to-zero `cartoon-render-gpu` T4 job (image :blender, built FROM :slim by Dockerfile.blender); each frame batch falls back to the web engine on failure and refused GPU starts fall back to the web finish job; ADVANCED_BLENDER=off disables it. Why: connect the benchmark 3D engine to real videos without risking a stopped render.
- Cartoon object library: CC0 packs are imported by hosted-renderer/cartoon/tools/build-library.py (Kenney) and the additive tools/import-quaternius.py (FBX/glTF -> GLB, rigged clips kept and seeked per frame with skinned ink pass) into assets/library with catalog.json; manifests reference objects as prop kind "asset" + id, the worker validator rejects unknown ids, prepare-scene copies only used files, and the Director sees only a per-story keyword shortlist (src/lib/object-library.ts); why: thousands of objects without bloating prompts or allowing invented ids.
- Long-form cartoons render 16:9 (1920x1080) through the same worker; the "map" world (hosted-renderer/cartoon/scene-map.js + map-overlay.js) bakes a relief map from bundled Natural Earth regions (assets/map, built by tools/build-map.py), and only a separate map-director pass may set world "map" using whitelisted region ids; why: geography must stay drawable and validated like every other prop.
